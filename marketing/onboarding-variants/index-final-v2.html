02 Magic Demo — Animation timeline

The hero animation of the onboarding. Auto-plays on screen appear, replays on chip tap.

Sequence

// Total: ~3.8s per demo cycle
0.0s   → reset (clear prompt, hide grid, hide caption, hide share btn)
0.2s   → start typing prompt (~50ms per char + jitter)
~1.5s  → prompt fully typed · show loading dots
~2.9s  → hide loading · reveal grid container
~2.9s  → photo 1 fades in (top-left)
~3.1s  → photo 2 fades in (top-right)
~3.3s  → photo 3 fades in (bottom-left)
~3.5s  → photo 4 fades in (bottom-right)
~3.8s  → caption fades in
~4.2s  → share button slides up + fades in

SwiftUI implementation

struct MagicDemoView: View {
  @State private var phase: Phase = .idle
  @State private var typedPrompt = ""
  let data: DemoData                // prompt, photos, caption

  enum Phase { case idle, typing, loading, revealing(Int), caption, complete }

  var body: some View {
    VStack {
      ChatBubble(text: typedPrompt, isTyping: phase == .typing)
      if phase == .loading { LoadingDots() }
      PhotoGrid(photos: data.photos, revealedCount: revealedCount)
        .opacity(phase >= .revealing(0) ? 1 : 0)
      if phase >= .caption { CaptionView(text: data.caption) }
      ShareButton().opacity(phase == .complete ? 1 : 0)
    }
    .onAppear { playSequence() }
  }

  func playSequence() async {
    try? await Task.sleep(for: .milliseconds(200))
    phase = .typing
    for char in data.prompt {
      typedPrompt.append(char)
      try? await Task.sleep(for: .milliseconds(Int.random(in: 40...80)))
    }
    phase = .loading
    try? await Task.sleep(for: .milliseconds(1400))
    for i in 0..<4 {
      phase = .revealing(i)
      try? await Task.sleep(for: .milliseconds(220))
    }
    phase = .caption
    try? await Task.sleep(for: .milliseconds(400))
    phase = .complete
  }
}

Replay on chip tap

Three chips (🌍 Italy / ☕ Coffee / 💼 Build). Tapping fires store.send(.demoChipTapped(.italy)) which:

  • Updates state.demoData with new prompt + photos + caption
  • Triggers a re-run of playSequence() via .task(id: state.demoData.id)
  • Photos for each demo are bundled assets (no PhotoKit yet — permission requested in step 03)
💡 Why animate this aggressively? The magic demo is the only place during onboarding where the user sees the actual product output. Every other step is setup. Making this moment cinematic (typing, loading, photos appearing one-by-one) wires the demo into the user's memory and converts curiosity into commitment.

03 Pillars editor

  • 4 pre-filled pillars: Cars / Food & Coffee / Build in public / Travel
  • Each chip uses a pastel accent matching its semantic color (blue / orange / purple / green)
  • "+ Add your own" input row with emoji auto-rotation (✨🎨📚🏋️🎵🌱…)
  • Min 2 · Max 7 pillars · CTA disabled outside that range
  • Rename inline (tap the text input) · Delete (×) · animations on add/remove

04 Live Sort (bounded scan)

  • Progress bars per pillar with per-pillar gradient (blue→purple, orange→red, green→cyan)
  • Live status text cycles: "Reading photo N…", "Tagging in Travel", "Almost there", etc.
  • Exit conditions (OR): 20 photos per pillar · 500 photos total · 100% library scanned
  • CTA stays disabled "Building your library…" until exit · then pulses blue "Continue · your gallery is ready →"
  • Scan continues in background after user advances to step 05

05 Your turn (first prompt)

  • "TYPE OR PICK" Geist Mono label inside a white rounded card
  • Prefilled text starts with "A post about " + active pill name
  • 3 pick pills generated from the user's confirmed pillars (top 3 by count)
  • Tap a pill → swap the text · live cursor blinks for typing affordance
  • CTA "Generate my first post →" fires SmartPostFeature.sendMessageTapped
  • On success, dismisses onboarding sheet · lands on Dashboard with the post pre-loaded in the Today card

META Edge cases & accessibility

  • Reduce Motion ON → magic demo skips typing animation, photos appear all at once with 0.2s opacity fade only
  • Photo permission denied → after step 03, recovery screen with deep-link to iOS Settings. Step 02 uses bundled samples regardless
  • Small library (< 100) → skip step 04 entirely · scan completes in <3s · land directly on step 05
  • Resumability → state persists via UserDefaults("onboarding.step") · scan progress restored from SwiftData counts on relaunch
  • Dynamic Type → Space Grotesk + Instrument Serif both clamp at .accessibility3
